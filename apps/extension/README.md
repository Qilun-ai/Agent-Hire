# Agent-Hire — Extension (MV3)

The user-facing product: a Chrome side-panel workbench that talks to the [backend](../backend/).
Built with React 19 + Vite + Tailwind v4 + `@crxjs/vite-plugin`.

**Phase 5a:** the discovery workbench — search, fit-scored job cards, profile editor, and the
tailor/apply panel with resume download.
**Phase 5b:** the agentic autofiller — [page-agent](https://github.com/alibaba/page-agent)'s
observe→act loop driven by the backend's configured LLM, plus the never-auto-submit guard and
`DataTransfer` resume attach, triggered from "Fill this page".

## Build & load

```bash
npm install
npm run build          # tsc --noEmit && vite build → dist/
npm test               # vitest + jsdom: submit guard / agent task / fill report
# Chrome → chrome://extensions → Developer mode → Load unpacked → select dist/
npm run dev            # HMR dev build
```

## What it does

The side panel is an apply assistant for your Agent-Hire apply cart (shared with the website
through `GET/PUT /api/v1/cart`):

- **Your jobs** — cart jobs first, then any job already prepared for applying (`GET /api/v1/extension/jobs`).
  The job whose page is open in the current tab is highlighted.
- **Open job** — opens the posting in a new tab; sign in to the portal there.
- **Fill this page** — click the site's own Apply button first, then fill. The page's fields (label,
  type, options, nearby text) go to `POST /api/v1/fill/plan`, which decides which saved value fills
  each one: built-in rules for obvious fields (email, phone, names, links), then the **decision model**
  (Kaggle notebook, else the decision-model API) chooses among your saved values and picks dropdown/radio
  options; fields that need a written answer, or that the decision model is unsure about, go to the main AI
  model in one call. Values come from Profile → Application answers (your facts and default answers), the
  job's data file (generated by the main AI only when it is ≥80% confident the job needs one; otherwise
  defaults and the résumé), and the résumé. Values are typed with native setters + input/change events,
  fields you already filled are kept, every write is read back, consent and captcha fields are left to
  you, and the tailored résumé is attached. With no decision model reachable, the main AI model maps the
  fields instead. Multi-page forms: go to the next page and fill again.
- **Fill with AI agent** — the fallback for unusual forms: page-agent driven by the backend's model reads
  the page and fills it step by step (slower; uses your AI model for every step). **Stop** ends a run.
- **Mark applied** — after *you* press Submit. Moves the job to Applications (and Analytics) and
  out of the cart (`POST /api/v1/leads/{id}/applied`).
- **Check AI** — one tool-call round trip to verify the configured model can drive the filler.

The panel follows the OS light/dark theme and uses the web app's neo-brutalist tokens.

## Layout

```
src/
├─ background.ts          service worker: opens panel, richest-frame FILL_PAGE, backend + LLM relay
├─ content.ts             tiny listener in every frame; lazy-loads fill/run.ts on "Fill"
├─ fill/run.ts            entry: decision fill by default, page-agent fallback (mode "agent")
├─ fill/decide.ts         decision fill: scan → /api/v1/fill/plan → apply → resume attach
├─ fill/scan.ts, apply.ts field descriptions for the plan; React-safe writes with read-back
├─ sidepanel/             App shell (connection + AI-readiness pills, fill log) + entry
├─ fill/                  guard · fileupload (+ guard.test.ts)
├─ shared/                api client · backend relay · types · messages · fillProfile · agentTask
└─ llm-client.ts          page-agent's fetch adapter → backend /api/v1/llm/chat/completions
```

## Autofill safety

- **Never auto-submits.** A capture-phase guard drops every untrusted (script) click on
  Submit/Apply/Next and every untrusted form submission; only real user clicks pass.
- **Never invents.** The agent task carries only stored profile facts and is told to omit
  anything it cannot answer.
- **No model key in the page.** page-agent's LLM calls are relayed by the service worker to the
  backend, which replays them on the configured provider; the agent never reaches another origin.
- **You click Apply.** The extension fills and (optionally) attaches the résumé; the final submit
  is always yours.
